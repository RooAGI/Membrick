# Release Notes: v0.10.4

## Starting reuses unchanged segment indexes

- Every start rebuilt the search index of every segment on disk, although few
  segments change between starts. A store of 46,795 documents in 618 segments
  took about 95 seconds to load.
- A segment's index now carries a fingerprint of exactly what a rebuild would
  write. A start reuses the index when the fingerprint, the document count and
  the file checksums match, and rebuilds only the segments that changed. On a
  copy of that store, a start went from about 130 seconds to about 14.
- The first start after upgrading is as slow as before, because stored indexes
  have no fingerprint yet. Upgrading or downgrading needs no migration.
