# Release Notes: v0.6.3

Date: 2026-10-17

Version 0.6.3 improves search review reliability and scale, and adds freshness
ranking for current-state queries.

## Search review and recording

- Rebuild the resident's in-memory search locator from the existing MCP
  telemetry ledger in bounded background batches. The ledger remains the
  durable source; no database or second search-history store is added.
- Bound review pagination by records, bytes, and response size. Exact review
  reads only the selected history record, and feedback lookups use resident
  memory state.
- Return an error instead of an unreviewable successful search when its
  telemetry record cannot be appended or assigned a review ID.
- Replace crash-sensitive create-new telemetry lock markers with an OS file
  lock, so an unlocked file left by a crashed process does not block later
  recording.

## Current-state freshness

- Add a configurable relative freshness contribution for current-state
  queries, applied after candidate retrieval and final reranking through
  `MemoryService`.
- Keep explicit temporal queries and other intents on their existing ranking
  paths. Configure the policy in `.membrick/server.toml`; no reindex is
  required to change ranking settings.

## Benchmark and documentation

- Record the latest 500-question LongMemEval-S run and provide a script for
  aggregating repeated benchmark reports without treating repetitions as more
  questions.
- Document the search-review storage design, freshness policy, and operational
  limits.

## Upgrade notes

Restart provider MCP sessions after upgrading so the resident loads the new
search-review index and freshness settings. The search-review index is
reconstructed from `.membrick/mcp-call-history.jsonl` after resident startup.
