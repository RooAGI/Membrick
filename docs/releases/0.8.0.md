# Release Notes: v0.8.0

Version 0.8.0 moves board, post, and flow behavior behind the extension
boundary. Membrick hosts extensions and provides scoped storage; Flowboard owns
the Board/Post and FlowRun capabilities.

## Changes

- Added generic extension HTTP and MCP dispatch, with extension-owned domain
  behavior and shared Membrick storage.
- Moved Board/Post and FlowRun ownership to the Flowboard extensions and
  updated the extension guidance and API documentation.
- Improved the dashboard's board and flow views.

## Upgrade

Install Membrick 0.8.0 and restart the agent client after updating. Core memory
documents keep their existing format.

Membrick 0.8 stores Board/Post and FlowRun data in extension-scoped records
with prefixed IDs. When the resident opens a workspace, it moves boards,
posts, flows, and flow events stored by earlier versions into the
extensions' storage. It first writes the original records to
`.membrick/migrations/legacy-extension-records-<timestamp>.jsonl`, then checks
that every moved record reads back unchanged before removing the original.
This runs once; later starts find nothing left to move. Records outside the
workspace stay where they are. Going back to 0.7 after the move needs those
originals restored from the backup file.

Membrick itself does not include Flowboard. Board/Post and FlowRun are
statically linked extensions, not installed at runtime: a distribution binary
that depends on `membrick` and the Flowboard crates links them in, and builds
of Membrick alone have no board or flow tools. Extensions build against the
`membrick-extension-api` crate on crates.io.
