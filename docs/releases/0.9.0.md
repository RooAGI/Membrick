# Release Notes: v0.9.0

Version 0.9.0 indexes more project file types. Besides Markdown, the project
scan now reads HTML pages, plain text files, and images that have a text
description.

## Changes

- HTML files (`.html`, `.htm`) are indexed as readable text. Headings, lists,
  tables, code blocks, and image alt text are kept; scripts, styles, and
  `<head>` are dropped. The page `<title>` becomes the top heading when there
  is no `<h1>`, and `<meta name="author">` sets the author.
- Plain text files (`.txt`) are indexed under their file name. Long files are
  split at blank lines into parts of about 2,000 characters so search results
  stay focused.
- Images (`.jpg`, `.jpeg`, `.png`, in any letter case) are indexed through a
  `.txt` description in the same folder: the full image name plus `.txt` if
  it exists (`photo1.jpg.txt`, `photo1.png.txt`), otherwise `photo1.txt`.
  Search results point at the image, and image results carry a `media_type`
  filter. The description is indexed only under its image, not again as
  plain text. If both description files exist, the `photo1.jpg.txt` one is
  used and `photo1.txt` is indexed as ordinary text. Images without a
  description are skipped, and image files are never read.
- Adding, editing, or removing any of these files triggers a reindex, the
  same way Markdown edits do.
- The project scan always starts at the project root. Earlier versions
  scanned only `docs/` when a project had a `docs/` folder, which left files
  such as `README.md` out of the index.
- `.membrick/server.toml` accepts `ignore_paths`, the list of paths the scan
  skips. Each entry is matched as part of the path relative to the project
  root. Without the setting, the built-in defaults apply: `node_modules`,
  `target`, `dist`, `build`, `vendor`, `coverage`, `.git`, and the Python
  environment folders `venv` (which also covers `.venv`), `.tox`, and
  `site-packages`. Setting it replaces the defaults. New installs write the
  defaults into `server.toml`.
- `.membrick/server.toml` accepts `allow_non_loopback = true`, so a resident
  started automatically by an agent can serve `resident_http_bind` on a
  non-loopback address such as `0.0.0.0`. A server token or JWT secret is
  still required. Before this, such a resident exited at startup, because
  only the `--allow-non-loopback` command-line flag could opt in. The
  startup errors now name the setting.
- A resident whose project path is too long for a socket inside the project
  now uses a socket name unique to that project, so two such projects served
  by one process no longer replace each other's socket.

See [Ingestion architecture](../ingestion-architecture.md#file-types) for how
each file type is read.

## Upgrading

- The first start after upgrading rebuilds the workspace index if the project
  contains HTML, text, or image files, or has a `docs/` folder.
- Projects with a `docs/` folder now also index files outside it, such as a
  root `README.md`. Text files anywhere in the project, such as
  `requirements.txt` or `LICENSE.txt`, are indexed too. Add folders or files
  to skip to `ignore_paths` in `.membrick/server.toml`. Existing
  `server.toml` files are not rewritten, so add the key yourself; include the
  defaults if you still want them skipped.
- No storage format or API changes. Document ids are unchanged, since paths
  were already relative to the project root.
