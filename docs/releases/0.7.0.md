# Release Notes: v0.7.0

Date: 2026-10-19

Version 0.7.0 gives each project root one resident that providers own,
writes the record store in crash-safe shards, cuts resident memory and idle
CPU, keeps captures free of copied memory and raw tool records, and adds
personal fact claims to search results.

## One resident per project root

- `membrick install` records the canonical root as `project_root` in
  `.membrick/server.toml`. A resident refuses to start, and the launcher
  refuses to spawn one, for a folder that is not an installed root. Claude,
  Codex and Gemini hooks walk up to the installed root and skip quietly when
  none covers their folder.
- Provider MCP adapters hold kernel-locked leases. The resident stops after
  the last lease is released and a configurable idle timeout
  (`resident_idle_timeout_seconds`, default 60).
- Each resident gets its own socket, `mb-<pid>.sock`, recorded in
  `runtime/resident.json`.
- Two lifecycle races are closed: the lease scan no longer deletes a live
  lease, and a signal-driven shutdown holds the lifecycle lock through flush.

## Storage

- Records are stored in 64 shards under `semantic/records-shards/`, with a
  manifest written last as the commit point. A checkpoint rewrites only the
  shards that changed. A process killed during a checkpoint keeps the
  previous records, and the journal replays acknowledged writes.
- The first checkpoint moves an existing `records.json` into shards and
  removes it.
- The semantic relation store is saved as `relations.bin` and reused when
  the record fingerprint matches, so restarts skip the relation rebuild.
- Rebuilt segments keep their lexical index on disk. Folders that the
  current snapshot no longer uses are deleted, both while running and at
  owner startup.

## Memory and CPU

- Records, chunks and source documents share one copy of each document's
  text. Segment indexes share the store's records instead of copying them.
- Tantivy readers use a manual reload policy, which removes one watcher
  thread per segment.
- The workspace watcher no longer caches every file in the project.
- An idle resident no longer rescans its file queue in a loop. On macOS this
  took idle CPU from about 6% to 0.1%.

## Capture

- Hooks wrap injected memory in `<membrick-memory>` markers, and captures drop
  it, so earlier memories are not copied into new ones. Tool calls and
  results keep the tool name and the start and end of their text. All
  providers share these rules.
- Capture stores one searchable turn document per batch instead of separate
  session-observation documents. Legacy observations are pruned.
- A compaction starts a new session segment for Codex and Claude. Roo gives
  each agent's compaction epoch its own segment, stores compaction summaries
  and compacted transcripts, and keeps recall within Roo's 6,000-byte
  context limit.
- A capture that replaces a record without claims keeps its temporal facts.

## Search

- Personal fact claims are extracted from captured text. Search results
  report each claim's state, such as current or superseded.

## Logging

- Every process logs one line per event with UTC time, level, role and
  process id. Set the level with `[logging] level` in
  `.membrick/server.toml`. The `MEMBRICK_MCP_TRACE_PATH` trace file is
  replaced by debug logs.

## Upgrade notes

- Rerun `membrick install` for each provider. Hooks and the resident will not
  run in a project until `.membrick/server.toml` names its `project_root`.
- The first start rebuilds `relations.bin` once. Later starts load it.
- After the first checkpoint the record store is sharded. Earlier releases
  cannot read it, so keep a copy of `.membrick/memory` before upgrading if
  you may need to go back.
- Restart provider MCP sessions after upgrading so they use the new resident.
