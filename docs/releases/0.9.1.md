# Release Notes: v0.9.1

Version 0.9.1 improves the provider dashboard and preserves more useful
provider activity for turn-level inspection.

## Changes

- The provider dashboard groups prompts, tool calls, memory retrievals,
  subagents, and token usage into turns. Subagent activity and token usage stay
  available even when the main event stream is busy.
- Tool cards can show the matched term or file path for injected memories and
  Membrick search results. Membrick search calls are treated as memory sources,
  not as downstream calls that used those memories.
- Full Membrick search responses load when their result details are opened, and
  dashboard text boxes include copy controls.
- The dashboard includes captured-memory index status and can retrieve a full
  search response by its recorded trace ID.
- Claude Code records subagent token usage from the subagent transcript, without
  counting the parent transcript's usage again.

## Compatibility

- A REST add that reuses a `request_id` with different content or session now
  returns HTTP `409 Conflict` instead of `422 Unprocessable Entity`. REST
  clients that branch on the status code must handle `409`. Rust, Python, and
  Node clients continue to classify either status as a rejected 4xx response.
- Retrying an explicit `request_id` created by an older version can recover its
  original session when the write remains in the same store and the messages
  and metadata match exactly. Changed payloads and different explicit sessions
  still conflict.

## Upgrading

Restart the agent client after updating. Existing memory data remains in place.
