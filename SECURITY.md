# Security Policy

## Supported versions

Security fixes are made for the latest released version of Membrick. Please
upgrade before reporting an issue you found in an older release.

## Reporting a vulnerability

Please do not open a public issue for a security problem.

Report it privately in one of these ways:

- Use GitHub private vulnerability reporting on the
  [Security tab](https://github.com/RooAGI/Membrick/security/advisories/new).
- Email lw@rooagi.com.

Include the affected version, the interface involved, steps to reproduce, and
the impact you expect. Do not include real user memory content or credentials.

## What to expect

- We aim to acknowledge reports within 5 business days.
- We will keep you updated while we investigate and fix the issue.
- We will credit you in the release notes if you want, once a fix is out.

## Scope

Membrick stores memory locally. Reports about unintended data exposure,
authentication or authorization gaps in the HTTP or MCP servers, unsafe
handling of stored data, and supply chain risks are all in scope.
